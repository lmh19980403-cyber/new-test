01 Cloud Infrastructure

云计算基础架构

云计算的核心不是把服务器搬到云上，而是构建高可用、可扩展、安全隔离、可观测和成本可控的业务基础设施。

核心产品理解

ECS部署业务应用、后端接口、AI 应用服务和轻量推理服务。
VPC构建私有网络，配合交换机、路由表和安全组实现网络隔离。
SLB / ALB流量分发、健康检查、故障摘除，支撑高可用入口层。
OSS存储文档、图片、日志、训练数据、知识库文件等非结构化数据。
RDS承载结构化业务数据，关注主备、备份、慢 SQL 和高可用。
Redis缓存热点数据、会话、限流信息，降低数据库压力。
CDN加速静态资源分发，降低源站压力，改善跨地域访问体验。
SLS / 云监控采集日志、指标和告警，支撑生产环境可观测性。

架构设计关注点

  • 高可用：多实例、多可用区、负载均衡、健康检查和故障切换。
  • 弹性伸缩：根据 QPS、CPU、内存、GPU 或队列长度自动扩缩容。
  • 安全隔离：使用 VPC、安全组、RAM 最小权限、数据加密和访问审计。
  • 可观测性：通过日志、指标、链路追踪和告警定位性能瓶颈与异常。
  • 成本优化：结合按量、包年包月、Serverless、缓存和资源释放策略控制成本。

02 LLM Foundation

大模型基础原理与应用开发

从 Transformer 到通义千问，再到 API 调用和 Token 管理，理解大模型应用不只是调用接口，而是一套完整工程链路。

Transformer 为什么成为大模型基础

RNN 必须按顺序逐词处理文本，难以并行，也容易在长文本中丢失前文信息。Transformer 使用 Self-Attention 让任意 Token 之间可以直接建立关联，同时更适合 GPU 并行训练，因此支撑了大模型规模化。

QQuery：我想找什么
KKey：我如何被匹配
VValue：我提供什么信息

关键机制

Self-Attention

计算词与词之间相关性，用注意力权重融合上下文信息。

Multi-Head Attention

多个注意力头从语法、指代、语义、逻辑等不同角度观察文本。

位置编码

为模型注入词序信息，解决注意力机制本身不感知顺序的问题。

FFN

对信息做非线性加工，增强表达能力，并承载大量语言模式和事实知识。

Decoder-only 与通义千问

现代生成式大模型多采用 Decoder-only 架构，通过预测下一个 Token 进行自监督训练。它可以把问答、写作、 翻译、代码和推理统一成“续写”任务，并利用海量无标注文本实现规模化训练。

  • RoPE / YaRN 长上下文位置编码
  • GQA 降低 KV Cache 压力
  • SwiGLU 增强 FFN 表达能力
  • RMSNorm 提升计算效率

应用开发要点

system设定模型角色、边界和输出规范。
user用户输入的问题或任务。
assistant模型历史回复，用于多轮对话延续。
temperature控制随机性，低值更稳定，高值更发散。
top_p控制候选词采样范围。
max_tokens限制输出长度，影响成本和响应时间。

大模型本身是无状态的，多轮对话依赖开发者持续传入历史 messages。Token 管理需要覆盖输入、输出、 历史对话、Prompt 模板和 RAG 上下文。

03 RAG & Knowledge Base

RAG 检索增强与企业知识库

RAG 通过“外部知识检索 + 大模型生成”降低幻觉、补充企业私有知识，并让答案具备可追溯依据。

标准流程

  1. 文档加载PDF、Word、Excel、PPT、网页、图片、OSS 文件、企业知识库。
  2. 文档解析普通文本、OCR、文档智能解析、大模型文档解析。
  3. 文本切片按固定长度、语义边界或标题层级切分，并设置 overlap。
  4. Embedding将文本转为向量，使语义相似内容在向量空间中距离更近。
  5. 向量检索将用户问题向量化后召回相关知识片段。
  6. Rerank对候选片段精排，提高最终进入上下文的信息质量。
  7. 答案生成结合问题、上下文和 Prompt 生成基于事实的回答。

优化方法

多路召回

融合向量检索、关键词检索、全文检索和元数据过滤。

Hybrid Search

兼顾语义相似和精确匹配，适合专业术语、法规编号、产品型号。

查询重写

将用户模糊问题改写为更适合检索的查询表达。

上下文压缩

筛掉无关内容，减少 Token 消耗并降低噪声。

递归检索

先定位片段，再向上扩展章节或向下补全细节。

句子窗口

保留命中句子前后语义窗口，避免回答只基于孤立片段。

评估指标

Faithfulness答案是否忠实于检索内容。
Answer Relevancy答案是否真正回应用户问题。
Context Precision召回内容中有效信息占比。
Context Recall关键证据是否被完整召回。

04 Fine-tuning

模型微调与优化

微调适合解决模型行为问题，例如固定格式输出、行业语言风格、文本分类、意图识别和结构化信息抽取。 RAG 更适合解决知识更新、私有知识问答和答案溯源问题。

优先选择 RAG

企业知识库、政策法规、产品手册、客服知识、内部文档问答。

考虑模型微调

固定格式、行业话术、特定风格、分类识别、稳定任务表现。

  • 全参数微调：效果上限高，但算力、数据和训练复杂度更高。
  • LoRA：只训练少量低秩适配参数，成本更低，适合企业快速验证。
  • 数据质量：样本准确、格式统一、标注规范和场景覆盖比训练技巧更关键。

05 Agent & Multimodal

Agent 与多模态应用

Agent 让大模型从“回答问题”升级为“完成任务”，通过规划、工具调用、记忆和结果检查参与复杂业务流程。

Planner理解目标并拆解任务。
Executor执行具体步骤。
Tool Use调用搜索、数据库、API、知识库等工具。
Memory保存历史上下文、用户偏好和任务状态。
Reflection检查结果并进行修正。
Multimodal处理文档、图片、表格和语音。

多 Agent 协作的关键不是数量越多越好，而是角色边界清晰、任务可拆解、结果可合并、成本可控制。

06 AI Engineering

AI 工程基础与分布式训练

深度学习框架负责模型构建、自动求梯度、调用 GPU，并连接分布式训练、推理加速和生产部署工具链。

TensorFlow 与 PyTorch

TensorFlow

Google 开源框架，工程部署生态成熟，适合已有 TensorFlow 技术栈和工业化部署场景。

PyTorch

Meta 开源框架，动态计算图、调试友好，是当前研究开发和大模型训练的主流选择。

大模型训练加速框架

DeepSpeed

通过 ZeRO、混合精度和显存优化，降低超大模型训练时单张 GPU 的显存压力。

Megatron-LM

通过张量并行、流水线并行和数据并行，把模型结构切分到多张 GPU 协同训练。

07 Production & Alibaba Cloud AI Stack

生产环境部署与阿里云 AI 技术栈

大模型应用从 Demo 到生产，需要解决稳定性、并发、成本、安全、监控和运维问题。

阿里云 AI 四层链路

基础资源层灵骏智算服务、GPU 集群、RDMA 高速网络
平台工具层PAI-DLC、PAI-Blade、PAI-EasyDistill
模型服务层通义千问、PAI-EAS、模型在线推理服务
业务应用层百炼平台、RAG 知识库、Agent、企业 AI 应用

关键产品能力

灵骏提供大规模 GPU 算力、高速网络和托管运维，降低自建智算集群门槛。
PAI-DLC支持 PyTorch、TensorFlow、DeepSpeed、Megatron 的分布式训练任务。
PAI-Blade通过算子融合、量化、剪枝和图优化提升推理速度、降低资源消耗。
PAI-EAS将模型部署为在线 API，支持弹性扩缩容、多版本、灰度和监控。
百炼整合通义千问、RAG、Agent、工具调用和应用编排能力。
ACK / FC / vLLM支撑容器化、Serverless 和高吞吐推理等不同部署形态。

生产化关注点

  • 高可用：多实例、负载均衡、健康检查、故障自动切换。
  • 扩缩容：根据 QPS、GPU、队列长度和响应延迟动态调整资源。
  • 安全合规：RAM 最小权限、API Key 管理、数据加密、脱敏和内容安全检测。
  • 可观测性：监控请求量、延迟、错误率、Token 消耗、GPU 利用率和 RAG 命中率。
  • 成本优化：模型选型、Prompt 精简、缓存、上下文压缩、推理加速和弹性资源。

Key Questions

关键技术问答

将核心概念整理成问题形式，便于快速定位知识点，也适合在页面中作为技术复习区。

Transformer 为什么比 RNN 更适合大模型？

Transformer 可以通过 Self-Attention 并行计算所有 Token，不需要像 RNN 一样逐词串行处理； 同时任意两个 Token 可以直接建立注意力连接，缓解长文本中的信息衰减问题。

Q、K、V 分别代表什么？

Q 表示查询意图，K 表示可匹配特征，V 表示实际信息内容。注意力机制用 Q 匹配 K， 得到权重后对 V 加权求和，从而融合上下文信息。

为什么现代生成式大模型多采用 Decoder-only？

Decoder-only 通过预测下一个 Token 训练，可以把问答、写作、代码、翻译和推理统一成续写任务； 同时适合海量无标注文本自监督训练，规模扩大后更容易涌现复杂能力。

RAG 和微调如何选型？

如果问题是企业知识更新、私有知识问答和答案溯源，优先选择 RAG；如果问题是固定格式、行业话术、 任务风格和输出稳定性，可以考虑微调。复杂场景可以采用 RAG + 微调组合方案。

阿里云 AI 技术栈如何从底层到应用串起来？

底层由灵骏等 GPU 算力提供训练和推理资源；PAI-DLC 管理分布式训练；PAI-Blade 做推理优化； PAI-EAS 部署在线模型服务；通义千问提供模型能力；百炼平台将模型封装为 RAG、Agent 和企业 AI 应用。
